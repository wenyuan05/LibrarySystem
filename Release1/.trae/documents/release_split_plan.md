# 图书馆系统 - 版本拆分实现计划

## 项目拆分策略

### 目标
将当前图书馆系统拆分为三个独立的Release版本，每个版本只包含对应release_plan.md中定义的功能，隐藏超前的功能。

### 拆分方法
1. 创建三个独立的Release文件夹：Release1、Release2、Release3
2. 每个Release文件夹包含完整的项目结构
3. 通过配置文件控制功能的显示/隐藏
4. 前端通过路由和导航菜单控制功能可见性
5. 后端通过API路由控制功能可用性

## 功能分析

### Release 1 功能
1. 用户登录/退出系统 (1.1)
2. 读者注册账户 (1.2)
3. 浏览和搜索图书列表 (1.3)
4. 锁定图书并在一定时间内借阅 (1.4)
5. 提交还书请求 (1.5)
6. 查看借阅历史 (1.6)
7. 图书管理员添加新图书 (1.7)
8. 图书管理员处理还书请求 (1.8)
9. 图书管理员查看所有图书信息 (1.9)
10. 管理员创建账户和管理用户信息 (1.10)

### Release 2 功能（增量）
1. 密码找回/重置 (2.1)
2. 续借图书 (2.2)
3. 预约图书和通知 (2.3)
4. 编辑和删除图书信息 (2.4)
5. 管理图书分类 (2.5)
6. 拉黑/解除拉黑逾期用户 (2.6)
7. 管理员设置系统参数 (2.7)
8. 管理员发布公告 (2.8)

### Release 3 功能（增量）
1. 读者编辑个人信息 (3.1)
2. 图书分类浏览 (3.2)
3. 查看热门图书 (3.3)
4. 图书管理员查看借阅统计 (3.4)
5. 管理员开启/关闭功能 (3.5)
6. 管理员查看系统日志 (3.6)

## 实现步骤

### 1. 创建Release文件夹结构
- 创建Release1、Release2、Release3文件夹
- 复制当前项目结构到每个Release文件夹
- 确保每个Release文件夹包含完整的项目文件

### 2. 配置文件设置
- 在每个Release文件夹中创建配置文件，定义该版本可用的功能
- 前端配置文件控制路由和导航菜单的显示
- 后端配置文件控制API路由的可用性

### 3. 前端代码修改
- 修改App.jsx，根据配置文件控制路由的注册
- 修改Sidebar.jsx，根据配置文件控制导航菜单的显示
- 确保超前功能的路由和菜单在低版本中不可见

### 4. 后端代码修改
- 修改路由文件，根据配置文件控制API路由的注册
- 确保超前功能的API在低版本中不可用

### 5. 测试验证
- 测试每个Release的功能是否正常工作
- 验证超前功能是否在低版本中被隐藏
- 确保核心功能在所有版本中正常运行

## 技术实现细节

### 前端配置
- 创建src/config/releaseConfig.js文件，定义每个版本的功能开关
- 在App.jsx中根据配置文件条件注册路由
- 在Sidebar.jsx中根据配置文件条件显示导航菜单

### 后端配置
- 创建backend/config/releaseConfig.js文件，定义每个版本的功能开关
- 在路由文件中根据配置文件条件注册API路由

### 版本控制
- Release1：只包含Release 1的功能
- Release2：包含Release 1 + Release 2的功能
- Release3：包含所有功能

## 测试计划

### 功能测试
- 测试每个Release的核心功能是否正常工作
- 验证超前功能是否在低版本中被隐藏
- 测试用户权限控制是否正确

### 集成测试
- 测试前后端集成是否正常
- 测试数据库连接和操作是否正常
- 测试系统性能和稳定性

## 风险评估

### 潜在风险
1. 配置文件错误导致功能显示异常
2. 路由控制不当导致超前功能可访问
3. 后端API控制不当导致超前功能可调用
4. 代码修改引入新的bug

### 风险缓解措施
1. 仔细测试每个Release的功能
2. 确保配置文件的正确性
3. 严格控制路由和API的注册条件
4. 保留原始代码备份，以便回滚

## 交付标准

1. 三个Release文件夹结构完整
2. 每个Release只包含对应版本的功能
3. 超前功能在低版本中完全隐藏
4. 所有功能在对应版本中正常工作
5. 代码修改最小化，不影响核心功能
