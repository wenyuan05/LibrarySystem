## 图书馆管理系统优化方案

### 1. 安全与权限控制

- **密码加密存储（高优先级）**
  - （已完成）在 `backend` 中引入 `bcrypt`，所有用户密码以哈希形式存储。
  - （已完成）示例用户（`admin/admin123`、`user1/user123`）在初始化时自动写入哈希密码。
  - （已完成）为兼容旧数据库，启动时会自动扫描 `users` 表，将检测到的明文密码迁移为哈希。

- **会话与鉴权机制（高优先级）**
  - （已完成）使用 JWT 管理登录状态：
    - 登录成功后返回包含用户 `id`、`username`、`role` 的 `token`。
    - 前端在登录成功后将整个用户对象（含 token）存入 `localStorage`。
  - （已完成）在后端增加鉴权中间件：
    - `authenticateToken`：校验 `Authorization: Bearer <token>` 头，解析出用户信息。
    - `requireRole('admin')`：限制仅管理员可访问的接口。
  - （已完成）保护关键路由：
    - 所有 `/api/books`、`/api/users`、`/api/borrow`、`/api/return` 相关接口均需携带有效 token。
    - 用户与借阅记录相关接口增加“本人或管理员”校验。

- **输入校验与基本安全**
  - （已完成）对用户名、密码、邮箱、ISBN 等字段做长度和格式校验（使用手写校验）：
    - 后端：添加了 `validateLoginBody`、`validateRegisterBody` 和 `validateBookBody` 中间件。
    - 前端：为登录和注册表单添加了客户端验证。
  - （已完成）为 API 统一返回规范化错误结构，隐藏内部实现细节。

### 2. 数据层与一致性

- **数据库约束完善**
  - （已完成）为 `books.isbn` 字段添加 `UNIQUE` 约束，从数据库层彻底保证 ISBN 唯一性。
  - （已完成）为 `users.username` 已有的 `UNIQUE` 约束保持不变，并在应用层继续做重复检查，提升用户体验。
  - （已完成）根据查询频率，为常用字段（如 `borrow_records.user_id`, `borrow_records.book_id`）添加索引，提高查询性能。

- **借阅流程约束加强**
  - （已完成）借阅书籍前除检查书籍 `status` 外，再检查是否存在该书籍尚未归还的借阅记录，防止逻辑缺口。
  - （已完成）在 `borrow_records` 上增加逻辑，避免出现同一本书被多个用户同时标记为“未归还”的情况。

### 3. 前端结构与用户体验

- **引入前端路由**
  - （已完成）使用 `react-router` 将当前基于 `activeTab` 的单页切换升级为多路由结构：
    - `"/login"`、`"/books"`、`"/users"`、`"/borrow-records"` 等。
  - （已完成）实现“受保护路由”组件：
    - 未登录用户访问受保护页面时自动跳转到 `"/login"`。
    - 普通用户访问仅管理员可用页面（如用户管理）时给出拒绝提示。

- **统一消息提示与状态反馈**
  - （已完成）用全局的通知组件（toast/snackbar）替换 `alert`：
    - 成功/失败消息以非阻塞的方式展示。
    - 可在 `request` 封装或自定义 hook 中统一处理 API 错误并弹出提示。

- **列表体验优化**
  - （已完成）为 `BookList`、`UserList` 等表格添加：
    - 前端搜索过滤（按标题/作者/用户名/角色等）。
    - 简单分页或“加载更多”以避免一次性渲染大量数据。
  - 后续如数据量增大，可扩展为后端分页接口（`?page=&pageSize=`）。

- **组件复用与 UI 规范化**
  - （已完成）抽取常用按钮、表格、对话框等基础组件，减少样式与逻辑重复。
  - （已完成）制定统一的颜色、间距、字号等设计规范，集中在样式变量（如 `variables.css`）中管理。

### 4. 工程化与可维护性

- **API 地址与环境配置**
  - 将当前硬编码的 `API_BASE_URL = 'http://localhost:3001/api'` 抽离到环境变量：
    - 在 `.env` 文件中配置 `VITE_API_BASE_URL`。
    - 在 `api.js` 中通过 `import.meta.env.VITE_API_BASE_URL` 获取，便于开发/测试/生产环境切换。

- **统一错误处理**
  - 后端：
    - 增加统一错误处理中间件，捕获路由中的异常并统一格式化输出。
    - 记录关键错误日志（包括栈信息），方便排查。
  - 前端：
    - 在 `request` 函数中规范化错误对象，所有组件只处理统一结构的错误。
    - 可封装自定义 hook（如 `useApiRequest`）以减少重复代码。

- **类型与测试**
  - 前端：
    - 逐步引入 TypeScript，为用户、图书、借阅记录等对象定义类型，提高重构安全性。
  - 后端：
    - 使用 Jest + supertest 为关键 API 编写基础集成测试（登录、增删改查、借阅/归还流程）。

- **日志与监控（可选进阶）**
  - 使用 `morgan` 或自定义中间件记录 HTTP 访问日志。
  - 在生产环境集成简单的健康检查接口和基础监控指标（请求量、错误数等）。

### 5. 推荐实施顺序

1. 实现密码加密、JWT/Session 鉴权与角色中间件，确保基础安全。
2. 完善数据库约束（ISBN 唯一、索引）和借阅流程的严谨性。
3. 升级前端路由体系、统一消息提示和列表体验。
4. 抽离环境配置，统一错误处理，并逐步引入类型和测试。
5. 视项目规模与需求，再考虑日志、监控和更复杂的运维能力。
